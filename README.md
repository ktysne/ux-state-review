# ux-state-review

UI の「状態」に関する 9 つの UX 規則をチェックし、対象アプリの文脈に合わせて適用するためのエージェントスキルです。
Claude Code と Codex のどちらでも使えます。

利用者が画面の前で立ち止まる場面（待つ、何もない、失敗した、権限がない、消す、終わった、入力が通らない）で、次に何が起きるか、何をすればよいかを画面が伝えているかを点検し、足りなければ補います。

## 9 つの規則

| 番号 | 規則 | 目的 | 対象となる状態 |
|---|---|---|---|
| 01 | 待ち時間を見える化 | 何を待っているか、どこまで進んだかが分かれば離脱が減る | 読み込み中、処理中 |
| 02 | 空状態に次の行動を | 空白を行き止まりにせず、最初の操作へつなぐ | データが 1 件もない |
| 03 | 0 件の理由を残す | 検索語と条件を残し、すぐ見直せるようにする | 検索や絞り込みの結果が 0 件 |
| 04 | 入力内容を失わせない | 通信失敗時も入力を保持し、再試行だけで戻れる | 送信や保存の失敗 |
| 05 | 必要な権限を具体化 | 必要な権限、管理者、申請方法を一画面で示す | 権限不足 |
| 06 | 保存状態を常に示す | 未保存、保存中、保存済みを作業中に確認できる | 編集中 |
| 07 | 削除対象と影響を明示 | 対象、戻せない影響、代替案を決定前に見せる | 削除や破壊的操作の確認 |
| 08 | 完了後の流れまで案内 | 受付内容、次の予定、確認方法まで伝える | 処理の完了 |
| 09 | 入力不備の直し方を示す | どの項目をどう直せば通るかを項目の近くで伝える | 入力不備（検証エラー） |

各規則の目的、チェック観点、対象外の条件、別の表現で満たす条件、実装上の注意は [skills/ux-state-review/references/rules.md](skills/ux-state-review/references/rules.md) にあります。

## このスキルの考え方

守るのは規則とその目的であり、特定の見た目ではありません。
規則を機械的に当てはめると、社内ツールに過剰な装飾を足したり、一瞬で終わる処理に進捗表示を付けたりして、かえって使いにくくなります。
そのため、このスキルは次の順で適用の可否を判断します。

1. その状態が実際に起きるか
2. 利用者がその状態で困るか
3. 既存のデザインシステムや UI 規約と衝突しないか
4. 実装コストに見合うか

判定は「満たす」「満たさない」「適用しない」「情報不足」の四つに分けます。
チェック観点どおりの表示ができなくても、別の手段で目的を達成できる場合は「適用しない」にせず、その手段の有無で判定します。

同じ立ち位置の姉妹スキルが三つあります。

- `ux-structure-review`：画面の構造（まとまりと優先順位）
- `ux-readability-review`：文字と文言（読みやすさ）
- `ux-load-review`：記憶、判断、操作の負担

## インストール

使うエージェントのスキルディレクトリに `skills/ux-state-review` を置きます。
スキルの形式（`SKILL.md` と参照ファイル）は Claude Code と Codex で共通です。

```bash
git clone https://github.com/ktysne/ux-state-review.git
```

ユーザー共通で使う場合：

```bash
# Claude Code
cp -r ux-state-review/skills/ux-state-review ~/.claude/skills/
```

```bash
# Codex
cp -r ux-state-review/skills/ux-state-review ~/.codex/skills/
```

特定のプロジェクトだけで使う場合は、そのリポジトリの `.claude/skills/`（Claude Code）または `.codex/skills/`（Codex）にコピーします。

クローンしたリポジトリをそのまま参照したい場合は、コピーの代わりにシンボリックリンクを張っても動作します。

## 使い方

スキルは、読み込み中、空表示、検索 0 件、送信失敗、権限不足、保存状態、削除確認、完了画面、入力不備といった状態の設計を含む作業で自動的に使われます。
明示的に使わせる場合は、Claude Code では `/ux-state-review` と入力し、Codex ではスキル名 `ux-state-review` を指示に含めます。

例：

- 「申請一覧画面と申請フォームの UI をレビューして」
- 「自動保存の保存状態表示と、削除確認ダイアログを実装したい」
- 「注文完了ページに何を載せるべき？」

レビュー結果は、規則ごとの判定表、優先して直す項目、開発者の判断を要する項目の三つに分けて報告されます。

## リポジトリの構成

```
skills/ux-state-review/
├── SKILL.md              スキル本体（進め方、規則一覧、適用判断の原則、報告の形式）
├── references/rules.md   規則ごとの詳細
└── evals/evals.json      動作確認用のテストプロンプト
```
